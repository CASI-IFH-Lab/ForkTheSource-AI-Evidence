## First: the P2 correction (D-102)

`is_malformed(ref) == (ref.title is None)` is **deleted.** `extract_references` now
returns an `ExtractionResult` NamedTuple:

```python
references, malformed_ref_ids = extract_references(doc)   # tuple form
result = extract_references(doc)                          # result.references, result.malformed_ref_ids
```

I took **option 1**, shaped as a `NamedTuple` so it unpacks like the tuple the card
asked for while still having names. Membership comes from the extraction attempt — no
reply validated against `Reference` after the configured retry — so a titleless work
survives it. Two tests pin the case that made the old predicate wrong: one asserts a
well-formed reply with `title: null` is **not** malformed, and one asserts that an
all-null reply and a garbage reply are *field-identical* and still correctly separated.
`is_malformed` was deleted rather than deprecated, with a test that it is gone.

## The D-037 question, answered honestly

**No real reference in either paper carries a `10.48550` DOI.** The arXiv-first branch
fires 22 times on `sample.pdf`, but always via `Reference.arxiv_id`, never via the
DataCite-DOI form. So:

- The **branch** is load-bearing on our own corpus — 22 of 40 references, over half the paper.
- The **specific regression D-037 warns about** — Crossref 404ing a `10.48550` DOI — is
  covered on our side only by `test_an_arxiv_doi_resolves_and_does_not_return_none` and
  by Roy's planted tripwire row. **Both need to stay.** Neither is redundant.

The recorded fixture `crossref_404.json` is a real HTTP 404 from
`api.crossref.org/works/10.48550/arXiv.1706.03762`, and a test asserts it really says 404,
so the evidence for D-037 lives in the repo rather than in the decision text.

## `is_preprint` is tri-state, from provider signals only (D-036)

| signal | value |
| --- | --- |
| arXiv resolver handled it | `True` |
| Crossref `type == "posted-content"` | `True` |
| Crossref `type == "journal-article"` | `False` |
| OpenAlex `type == "article"` **and** primary source `type == "journal"` | `False` |
| anything else | `None` |

The recorded preprint fixture is D-036's argument in one field: **Crossref returns
`container-title: []` for a preprint.** A venue string could not have produced that
`True`, because there is no venue string. A source-level test asserts neither resolver
branches on venue text.

`None` is tested as distinct from `False`, because collapsing them asserts "definitely
the published version" on missing data, which D-020 forbids.

**One signal deliberately left on the table**: OpenAlex has its own `type: "preprint"`
and `source.type: "repository"`, and both appear in the wild. The card enumerated the
signals allowed to produce a boolean and those are not among them, so they yield `None`.
That is most of the `None=9` in both columns above. If you want them promoted to `True`,
say so and it is a two-line change plus a test — but it is your call, not mine, because
it moves the distribution P5's `version_mismatch` rule consumes.

## Found and fixed: an arXiv namespace bug

`doi` and `journal_ref` are in **arXiv's own XML namespace**, not Atom's. The first
version of the normaliser read `atom:doi`, which matches nothing — so it returned `None`
on every entry, silently, forever. That field is exactly P5's `version_mismatch` input:
when an author registers the published version, arXiv reports its DOI.

Fixed, with `tests/data/resolver_fixtures/arxiv_atom_published.xml` recorded from
arXiv:1207.7214, which carries both:

```
doi:         10.1016/j.physletb.2012.08.020
journal_ref: Phys.Lett. B716 (2012) 1-29
is_preprint: True          <- still the preprint record we resolved
```

Neither of the other two fixtures has these fields, and a test asserts they stay `None`
there rather than becoming empty strings.

## D-007 and the lazy import (D-103)

`crossref.py` calls `settings.crossref_mailto()` **at module import** and raises without
it, as the card requires. `resolver.py` imports `crossref` **lazily**, because an eager
import makes `src.resolvers` unimportable on a clone with no `CROSSREF_MAILTO` — which
would break `pytest --collect-only`, the S0 interface probe and CI, none of which make a
request. Verified: with the mailto absent, `resolver`, `cache`, `arxiv` and `openalex`
all import fine, `crossref` raises with an actionable message, and `resolve()` degrades to
OpenAlex.

Deferring is paid for: the first failed import emits a **one-time `RuntimeWarning`** to
stderr naming `CROSSREF_MAILTO` and saying the run is OpenAlex-only. A `notes` entry
alone was not enough — a caller may discard the list, and running OpenAlex-only while the
operator believes Crossref is live is exactly the silent degradation D-007 exists to
prevent.

**Teammates need `CROSSREF_MAILTO=<your asurite>@asu.edu` in `.env`** or every Crossref
lookup falls through. It is already in `.env.example`.

## What the ResolvedSource model could not represent

Three things came back from real providers with nowhere to go:

1. **PMIDs.** Every PLOS reference prints one, and Crossref/OpenAlex return them. There
   is no `pmid` field, so they live in `raw` only. Not a blocker — nothing resolves by
   PMID today — but if we ever want PubMed as a fourth provider it needs a contract field.
2. **arXiv `journal_ref`** — the published venue of a preprint. Stored in `raw` as
   `arxiv_journal_ref`. `venue` stays `"arXiv"` because that is the record we resolved.
3. **Crossref `publisher`** and **OpenAlex `type`/`source.type`** — kept in `raw`, not
   modelled. Fine as is; `raw` is where a P5 rule can reach for them.

Nothing was lost or truncated in a way that loses information: `raw` is trimmed to the
fields used plus a few, and every result records `_lookup_url`.

## One caveat for P5 about the title branch

Branch 3 is a *search*, and search returns the best hit, not the right hit. Resolving
`"The Economics of Reproducibility in Preclinical Research"` by title returned
`10.1371/journal.pbio.1002626` — a different PLOS Biology article. **Title-branch results
are candidates, not confirmations**, and `title_similarity` is what has to gate them. On
`plos_sample.pdf` 14 of 34 references have no DOI and therefore took this branch.
