## FIX A — the hyphen is decided at the join, not over the joined string

`_rejoin` drops a hyphen that was the last character before a line break and keeps every
other hyphen. Measured on both papers first, because the rule turned out to have a case
nobody had named:

```
30 line-end hyphens across the two papers
~26 syllabic     im-/age, Convolu-/tional, sci-/ence, Pharma-/ceutical, Can-/cer, AR-/RIVE
  3 genuine      attention-/based, pre-/clinical, over-/passaged
  1 IDENTIFIER   10.1016/S0140-/6736(13)62227-8   <- a DOI split across the break
```

**The DOI is the one exception in the code**: a hyphen preceded by a digit is kept. A
corrupted title finds nothing; a corrupted DOI finds *somebody else's paper* and asserts
it confidently, which is the failure this project exists to prevent.

**The measured cost, asserted in a named test so it cannot grow unnoticed:**
`attention-based` → `attentionbased` and `pre-clinical` → `preclinical`. Two words against
~26 repaired, and separating them needs a dictionary. `_rejoin`'s docstring carries the
count; if someone adds a lexicon later, `test_a_genuine_compound_broken_at_its_own_hyphen
_loses_it` is the test that tells them what changed.

**Cache: `PROMPT_VERSION` deliberately NOT bumped.** Entry text is already in P2's cache
key, so the ~20 entries whose text changed miss and the other ~54 stay warm. Bumping
would have taken all 74 cold to invalidate the 20 that moved.

## FIX B — D-108, and it needed a re-ordering the ruling did not anticipate

The rule as ruled: on `_lookup_branch == "title_search"`, a weak match — below
`title_weak`, **or** no author overlap — is `unresolvable`, not `conflict`.

Implementing it exposed two ordering problems that the one-line version does not survive:

1. **`doi_mismatch` short-circuited above it.** `plos` R24's weak title search returned an
   unrelated book chapter, and the differing DOI on *that* record then read as a
   `conflict` — the same bad search wearing a stronger word. D-108 now sits **above** the
   `doi_mismatch` check. It stays **below** the retraction check: suppressing the
   highest-severity thing a provider tells us is not a call this branch makes.
2. **It would have swallowed D-104's gate.** A *strong* title-search hit with no author
   agreement is "we found a plausible record and want it confirmed" (`needs_check`), a
   different statement from "we found nothing". D-108 carries `not strong_title` so the
   two are disjoint. This is what keeps `sample` R12 (sim 0.97, the same paper with its
   title reordered) at `needs_check` rather than burying it.

Named tests for all three FINDING 1 examples at their measured signal values (R11 0.66,
R13 0.35, R33 0.07), plus the ordering cases and the branch-scoping cases.

## P6 — the seven stages

| stage | does | model on the strip |
| --- | --- | --- |
| `intake` | `parse_pdf` | `None` |
| `extract` | `extract_references` + `extract_claims` | **`models.extractor`** |
| `resolve` | `resolve` per reference | `None` |
| `evidence` | `build_evidence`, **with `malformed_ref_ids`** | `None` |
| `verdict` | `judge_fn` | **`rule_based`, or `models.judge` when injected** |
| `priority` | `compute_priority` | `None` |
| `ledger` | invariant, then `save_ledger` | `None` |

**The `verdict` model name is the one that actually runs.** On the default path that is
the string `rule_based`, which is also the `judge_model` on every `Verdict`, so the strip
and the ledger say the same thing. Naming the configured AIR judge there while
`rule_based_status` does the work would put a model on screen that was never called, and
the entire value of the strip is that it is true. When A3 injects a judge, it reports
`settings.model_for("judge")`.

**A misspelled stage key raises here rather than failing silently downstream.** D-204 is
explicit that an unrecognised name lights nothing and does not raise — so `_emit` checks
membership of `STAGE_KEYS` and raises `PipelineIntegrityError`. The test asserts the
emitted sequence against **its own hand-copied tuple**, not against `dashboard.theme`:
importing that would cross a lane boundary *and* make the test vacuous.

**A progress callback that raises does not take the run down.** A chip that fails to
light must not cost a correct ledger.

**The counts invariant** runs before the write, and `_check_counts` is split out so a test
can arm it against a stub — through `Ledger` alone it is close to unfailable, and an
invariant nobody can watch fail is one nobody can trust.

## Three things for Roy, one of which is the important one

**1. The extractor invented an arXiv identifier.** `paper1` R24's printed text is
`"M. Śmieja, B. C. Geiger, Semi-supervised cross-entropy clustering with information
bottleneck constraint, arXiv preprint (2017)."` — **no id in it**. The extractor returned
`arxiv_id: 1706.05555`, the resolver dutifully fetched it, and arXiv says that id is
*"Goldstone and Higgs Hydrodynamics in the BCS-BEC Crossover"*. On the `arxiv_id` branch
an identifier is treated as tying the record to the reference, so the mismatch scored
`conflict` — our only false conflict on the demo paper, on the D20 version-pair trap row.

Scanned all 104 references across the three papers: **1 invented identifier, this one.**
Isolated, not systemic — but it is our own pipeline producing the exact failure shape the
project exists to catch. The cheap guard is a post-condition in `_reference_from_reply`:
a `doi` or `arxiv_id` the model returns must appear in the entry's printed text, or it is
dropped. That is a P2 change with cache consequences and it is not in this PR.

**2. R06 (D07, wrong year) reads `unresolvable`, label says `needs_check`.** The title
search returned a different paper entirely, so the 38-year delta is measured against the
wrong record. Not a D-108 cost — before D-108 this was `conflict`, which is not
`needs_check` either.

**3. `test_the_whole_page_runs_end_to_end` went red the moment a real ledger existed.**
The banned-terms scan flagged `fraud` — from `plos` R22's own title, *"Reproducibility:
fraud is not the big problem"*. The rule governs the language **we** produce about a
paper, not a paper's title, and refusing to render a real title would be a worse failure
than the one the rule prevents. The live-page test now strips reference-sourced strings
before scanning; the recorder tests still scan everything they draw. **@arsha this is a
one-function change in your test file — shout if you want it done differently.**
