## FINDING 1 — 16 of 74 correct citations classify as `conflict`. Your ruling.

The card's mapping sends "weak title + no author overlap" to `conflict`. On real input
that fires on references that are **correctly cited**, because the disagreement is
between the citation and **our own failed title search**, not between the citation and
reality:

```
R11 sim=0.66 auth=0.00  printed : Deep residual learning for im-age recognition
                        resolved: RARN: Lightweight Deep Residual Learning with Attention...
R13 sim=0.35 auth=0.00  printed : Long short-term memory
                        resolved: Forecasting Cryptocurrency Prices Using Hybrid Long Short...
R33 sim=0.07 auth=0.00  printed : Governing the Commons: The Evolution of Institutions...
                        resolved: Preface
```

`conflict` is the second-highest severity and, in this project's vocabulary, asserts the
citation disagrees with the record. Here the citation is fine and we resolved badly.
That is the accusation shape the ADDENDUM exists to prevent, and it will show up in R2's
baseline as ~22% spurious conflicts.

**Implemented as specified anyway**, because the mapping is the spec. The one-line fix,
if you want it: on `_lookup_branch == "title_search"`, a weak match is `unresolvable`
("we did not find it"), not `conflict` ("it disagrees"). D-104 and D-107 record the hole.

## FINDING 2 — line-break hyphens corrupt titles, which is what poisons those searches

```
printed: "Deep residual learning for im-age recognition"     -> should be "image"
printed: "On the reproducibility of sci-ence: ..."            -> should be "science"
printed: "Convolu-tional Sequence to Sequence Learning"       -> should be "Convolutional"
```

17 of 40 `sample.pdf` entries contain a hyphen, **genuine ones (`short-term`,
`encoder-decoder`) mixed with line-break artifacts**, so no rule over the joined string
can separate them. P2's hyphen rule was written for `attention-`/`based` and is correct
for that case.

**The clean fix is in P2, not here, and it is cheap**: `_rejoin` knows exactly where it
joined two lines. Keep the hyphen only when it was already mid-line; drop it when the
hyphen was the last character before a line break and the next fragment starts lowercase.
P2 has the information; the joined string does not.

## The signals

| | |
| --- | --- |
| `title_similarity` | token-sort ratio over casefolded, de-accented, punctuation-stripped text. **`difflib` only** |
| `author_overlap` | Jaccard over normalised surnames |
| `year_delta` | `abs()`. D-105 |
| `doi_match` | tri-state; `None` is the common case (0/40 DOIs on `sample.pdf`) |

**`difflib` only, not "rapidfuzz if available".** The two do not agree to two decimal
places, the thresholds consuming this are 0.92 and 0.70, and R2 scores a baseline
against it — so "whether rapidfuzz happens to be installed" would become an input to the
confusion matrix and two teammates would get different metrics from the same ledger. If
we want rapidfuzz it should be a **pinned** requirement, not an optional import. Your
call; it is a one-line swap.

## `malformed` and the frozen signature — flagging, not deciding

`build_evidence(ref, resolved, ledger_refs)` has nowhere to put P2's malformed set
(D-102). It is an **optional trailing keyword with an empty default**, so every
three-positional call site keeps working and nothing in Arsha's or Roy's lane breaks.

**The cost: a caller that omits it gets no `malformed` indicator at all.** P6 is mine and
will pass it, but the gap is silent rather than loud. If you want it mandatory, that is a
signature change and needs both other lanes to agree.
