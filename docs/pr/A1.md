## What this changes

Adds `src/judge/` — the AIR-hosted LLM judge, the prompt that carries the project's
honesty boundary, and the folded-in critic. `judge_reference(ref, ev, fallback_fn=None)`
classifies one reference into one of the four contract statuses and **never raises**:
every failure path degrades to a deterministic verdict and records which path answered in
`Verdict.judge_model`. `gate_batch(verdicts, total)` runs three code checks over a batch —
one verdict per `ref_id`, counts summing to `total`, and a banned-term scan read live from
`settings.banned_terms()`.

Nothing outside my lane is touched. `src/judge/` imports only `src.contract`,
`src.settings` and `src.llm` (tier 1), which `tests/test_layout.py` enforces in both
directions. The seam to Ritik's lane is the injected `fallback_fn`, not an import; A3 fills
it with `rule_based_status`.

## Statuses and indicators touched

**Can now emit:** all four statuses — `verified`, `needs_check`, `conflict`,
`unresolvable`. The judge reads all six indicators out of `MatchEvidence` and acts on two
of them in code (`retracted`, `malformed` — D-201); the other four inform the model through
the prompt.

**Deliberately cannot:** A1 emits **no** indicators. Indicators are P5's to set on
`MatchEvidence`; the judge consumes them and never adds one. It also never writes a
`ref_id` the model supplied — `ref_id` is copied from our own record every time.

## Anything I was unsure about

1. **The live smoke test skipping instead of failing (D-203).** The AIR gateway dropped
   connections repeatedly while I was building this — one run skipped on a timeout and the
   next two passed in 1.8s each, nothing changed in between. I judged that a live test that
   goes red on VPN weather makes R6's "pytest is green before you self-merge" meaningless
   for all three of us. It still fails hard if the gateway answers and we mishandle the
   answer. Say so if you would rather it were a hard failure.
2. **`gate_batch` raising on a counts mismatch.** There is no per-entry repair for a
   missing or duplicated verdict, so it raises rather than returning a batch it knows is
   wrong — the same stance as `Ledger.assert_consistent()` and A2's refusal to render
   inconsistent counts. The alternative, returning the batch and letting the dashboard
   catch it, moves the failure one layer further from its cause.
3. **`rejudge_fn` on `gate_batch` is keyword-only and optional**, so the frozen
   two-argument signature in §7 is exactly what a caller sees. Nothing supplies one yet;
   noted as Phase 2 in `progress/arsha.md`.
4. **The parse-noise ceiling lands on `unresolvable`, not `needs_check`, when nothing
   resolved.** That is to agree with D-012's golden label. If Roy's corpus disagrees, the
   line to change is one `if` in `apply_evidence_rules`.
