# P1 — PDF intake and normalization

`parse_pdf(path) -> ParsedDocument` is live. Plain code, no LLM, no network, no import
of `src/contract.py`.

## Public interface

```python
from src.ingest.pdf_parser import parse_pdf, ParsedDocument

doc = parse_pdf(path_or_bytes_or_file, name=None)   # -> ParsedDocument
```

```python
@dataclass
class ParsedDocument:
    name: str                    # basename, or a file object's .name, else "<bytes>"
    pages: list[str]             # one per page; a page with no text is "", never dropped
    tables: list[Any]            # [] in Phase 1
    body_text: str               # text before the references heading
    references_text: str         # text after it; the heading belongs to neither
    ref_start_page: int | None   # 1-BASED, so pages[ref_start_page - 1] is that page
    notes: list[str]             # everything that did not go cleanly; [] means clean
```

`extract_pages`, `extract_text` and `locate_bibliography` stay exported for the B0
tests but are internals. `locate_bibliography` no longer raises — it is a thin view
over the same split. **New code calls `parse_pdf`.**

`run(pdf, config)` takes config as a required positional now, matching every other
stage entry point so P6 can call them all the same way. P1 reads nothing from it; pass
`None` to say so explicitly. It still returns `{pages, text, page_count}`.

## The one thing in here that is not on the card

**pdfplumber's default `x_tolerance` glues real papers into one word per line.** Both
real fixtures, not one:

```
default:                 [1] JimmyLeiBa,JamieRyanKiros,andGeoffreyEHinton. Layernormalization.
default (PLOS):          1. CollinsFS,TabakLA(2014)NIHplanstoenhancereproducibility.
x_tolerance_ratio=0.15:  [1] Jimmy Lei Ba, Jamie Ryan Kiros, and Geoffrey E Hinton. Layer normalization.
```

Two out of two real papers, so this is the common case. Every extraction now passes
`x_tolerance_ratio=0.15`, which scales the tolerance with font size instead of fixing
it in absolute points — a 6pt footnote and 10pt body text cannot share one absolute
tolerance. 0.15 was measured, not chosen: at 0.25 the body text glues back together, at
0.10 words start splitting mid-word, and the synthetic fixtures are byte-identical
either way. `test_word_spacing_survives_extraction` is the only test that fails if
someone removes it — without it, everything else still passes while P2 silently
receives unsplittable text.

## Found in the tree, and fixed here because it blocked the work

**`.gitignore`'s `data/` rule silently swallowed every test fixture.** Unanchored, it
matched `tests/data/` as well as a root-level `data/`. B0's two fixtures had to be
force-added to get in, and every fixture added since was silently skipped by
`git add -A` — which is exactly how P1's four new fixtures nearly failed to reach the
branch. `git status` showed a clean tree with the files sitting there untracked.
Anchored to `/data/`. If a lane wants a nested scratch `data/` ignored, add it
explicitly. **This is worth knowing for Roy: `eval/corpus/` PDFs are not affected, but
anything you drop in a nested `data/` was invisible to git until now.**

## For P2: `references_text` has a tail

On `sample.pdf` the 40 reference entries come out in clean reading order — every marker
`[1]`..`[40]` present and monotonic. But `references_text` is 9,456 chars and **2,504 of
them (26%) come after entry `[40]`**: pages 13–15 are the paper's "Attention
Visualizations" appendix, and pdfplumber renders those figures' rotated axis labels as
reversed single-character lines (`'tI'`, `'si'`, `'ni'` — "It", "is", "in" backwards).

```
page 10:  3111 chars,  4 entry markers,  1 line of <=3 chars
page 11:  3215 chars, 20 entry markers,  1 line of <=3 chars
page 12:  3213 chars, 16 entry markers,  1 line of <=3 chars
page 13:   812 chars,  0 entry markers, 19 lines of <=3 chars   <- appendix figures
page 14:   815 chars,  0 entry markers, 61 lines of <=3 chars
page 15:   818 chars,  0 entry markers, 61 lines of <=3 chars
```

P1 does not truncate, because knowing where the list ends means parsing entries, and
that is P2's pre-splitter. **P2 should cut at the last entry marker rather than trusting
the end of `references_text`.** The clean part is genuinely clean:

```
[23] Minh-Thang Luong, Quoc V. Le, Ilya Sutskever, Oriol Vinyals, and Lukasz Kaiser. Multi-task
sequence to sequence learning. arXiv preprint arXiv:1511.06114, 2015.
[24] Minh-Thang Luong, Hieu Pham, and Christopher D Manning. Effective approaches to attention-
```
