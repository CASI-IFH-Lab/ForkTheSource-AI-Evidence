## Config: gaps closed, critic keys dropped

Every value came from the plan, not from judgement. Added: `resolvers.cache_ttl_hours`
(72), `resolvers.providers`, `resolvers.mailto` (placeholder — each of us puts our own ASU
address in), `llm.timeout_seconds` (60), `llm.max_retries` (1), `cache.schema_version`,
the four `thresholds` (0.92 / 0.70 / 0.60 / 1), and `priority.severity` (the four status
weights).

`llm.timeout_seconds` is deliberately separate from `resolvers.timeout_seconds: 10`: that
one is the HTTP timeout, and reusing it for a reasoning model on a long bibliography would
time out every judge call.

**Dropped `models.critic` and `critic_temperature`.** You asked me to decide rather than
leave it silent: A1's `gate.py` is three code checks — one verdict per `ref_id`, counts sum
to total, banned-term scan of rationale and checks. None of that is an LLM call, so those
were keys nothing could ever read. `tests/test_config.py` now asserts both are absent, so
re-adding one is deliberate and arrives with a failing test.

The first pass's proposed `thresholds: {verified: 0.9, ...}` shape was **discarded**. P5's
classifier is a rule mapping over signal thresholds, not a confidence band per status; the
proposed shape would have quietly built a different classifier than the one R2 measures.

Also added `data/` to `.gitignore`, per Section 8 — P6 writes `data/output/*.json` and A3
saves uploads to `data/uploads`.
