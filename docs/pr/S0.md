# S0 — the status system

Tooling only. Touches no module under `src/`, not `config.yaml`, and no existing test.

## Why this lands before P1

Three people are about to work three lanes in parallel for five hours. The failure mode
this is designed against is someone asking *"is P2 merged yet, and what does it export"*
in chat and waiting eight minutes for an answer — three times an hour, three people, for
five hours. `git pull && cat STATUS.md` answers it in one command, and STATUS.md is
ordered so the answer is readable in ten seconds: **open blockers first**, because
anything in that section is a person sitting idle right now.

## Design decisions worth arguing with

**The tool may never fail.** Every input is optional and every section is independently
guarded by `_safe()`: if git is absent, `progress/` is empty, `pytest` hangs, or a module
raises on import, that *section* says so and the script still exits 0. The only non-zero
exit is the deliberate one from `--check`. A status tool that crashes is worse than no
status tool, because the next thing that happens is everyone goes back to asking in chat.

**Blockers are shown until explicitly retired.** Every `REQUEST` and `BLOCKED` block
anywhere in any file stays in the top section until the same person later appends a
`MERGED` block for the same module. Since the files are append-only, retiring is an
append: `## 2:05 — P3 MERGED` retires `## 1:00 — P3 BLOCKED`, and `## 2:20 — REQUEST
MERGED` retires a request (a request heading names no module of its own, so `REQUEST`
*is* its module). This errs toward showing a stale request, on purpose: a stale entry
costs a reader five seconds, a hidden one costs somebody an hour of sitting still.

**Fenced text is not parsed.** That is what lets every progress file carry a worked
example that does not report itself as real status.

**A heading must name a module.** `## 1:00 — MERGED` is reported as unparseable rather
than accepted, because a module-less block cannot be retired or attributed. Unparseable
headings are listed with file and line in the blockers section — silently dropping one
would make STATUS.md confidently wrong, which is the only outcome worse than stale.

**The interface list is hardcoded, not derived.** It is the contract the lanes agreed to,
so it has to be able to show a symbol as missing when nobody has written the module yet.
Deriving it from the tree would only ever report what already exists.

**Imports for the probe run in-process** with output swallowed, warnings silenced, and
`except BaseException` (so a module that calls `sys.exit` at import cannot take the tool
down). The one thing this does not survive is a module-level infinite loop; if that ever
happens, move the probe into a subprocess with a timeout.

**No amending from the hook.** `post-commit` leaves STATUS.md modified in the working
tree rather than amending the commit you just made — amending from a hook rewrites
history under you. On main the Action commits it; on a branch, include it in your next
commit or ignore it.

**The Action fails loudly.** If the push is rejected it prints the exact setting to change
and exits non-zero. We would much rather see a red X than believe a six-hour-stale
STATUS.md.

## Known friction

Because the hooks rewrite a tracked file, git will sometimes refuse a pull with "your
local changes would be overwritten". The fix is always `git checkout -- STATUS.md` and
pull again, never a manual merge. Documented in the README. The alternative — untracking
STATUS.md — would mean a fresh clone has no status at all, which defeats the point.

The branch-tip age column is floored to a 15-minute bucket for the same reason. With
minute precision the first draft rewrote one line of STATUS.md every single minute, which
would have made the local pull friction constant and `--check` almost meaningless. The
column exists to answer "has this branch been sitting for hours", so 15 minutes is all
the precision it needs.

## Follow-up: the recursion guard was skipping real pushes

The first version of `.github/workflows/status.yml` used the guard as specified:

```yaml
if: "!contains(github.event.head_commit.message, '[status]')"
```

On the merge of S0 the job ran and **skipped itself**. The squash commit body contained
the marker literally — in the bullet describing this very workflow — so `contains()`
matched a commit that had nothing to do with the bot.

Changed to `startsWith()`. The bot's commit subject is always exactly
`[status] regenerate STATUS.md`, so a prefix match is airtight for the only case the
guard exists for, and a commit body that quotes the marker no longer silently disables
the refresh. `contains()` fails in the worst possible direction here: STATUS.md goes
quietly stale while everyone keeps trusting it, which is the exact outcome this whole
system exists to prevent.
