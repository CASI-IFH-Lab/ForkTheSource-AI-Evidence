## 🔴 One action item before this is safe to build against

**`version_mismatch` must require VENUE divergence, not year alone.** This is a constraint
the corpus places on **P5**, which is unwritten code, and it has to be agreed at **Sync 1**.

Without it, P5 emits `version_mismatch` on every wrong-year reference, and because indicator
matching is exact-set, all three wrong-year defects (`D07`-`D09`) score as **misses on a
correct classification** — recall drops to 18/21 and fails the plan's ≥ 19/21 target while
the pipeline is behaving properly.

I have a concern with the ruling's *formulation* and a recommendation in
[`docs/defect_catalog.md`](../defect_catalog.md) §3. Short version: venue strings are the
least normalised field in any bibliography (`Journal of Machine Learning Research` vs
`J. Mach. Learn. Res.`), and there is **no venue threshold in `config.yaml`** to tune a
similarity test against. **Define it categorically instead** — `version_mismatch` fires when
exactly one of the two records is a preprint. That is a boolean, needs no new config key,
and encodes the plan's own words. Every label in this PR stays as written either way.

## The nine rulings

All nine ambiguities the first pass raised are now decided. Nothing is left for R2 to decide
silently. Full reasoning in [`FORMAT.md` § Rulings](../../eval/golden/FORMAT.md#rulings).

| # | Question | Ruling | Changed from the first draft? |
|---|---|---|---|
| 1 | Wrong year | `needs_check` + `[]` | **Yes** — was `[version_mismatch]`. Carries the P5 constraint above. |
| 2 | Malformed entry | `unresolvable` + `[malformed]` | Confirmed. The plan does **not** contradict itself: P5's line governs *status from evidence*, A1's governs *confidence direction*. "Never toward conflict" forbids escalation; it does not mandate `needs_check`. Both variants documented; R1 injects the severe one. |
| 3 | Version pair | `verified` + `[version_mismatch]` | Confirmed as recommended. |
| 4 | Do the traps count in the 21? | **Yes** | Resolved by redefining recall as label agreement: a trap is detected when the pipeline gets it *right*, which for a trap means not flagging `conflict`. R2 also prints them as a separate named row. |
| 5 | Mangled author list | `needs_check` + `[]` | Confirmed, with the DOI-less injection constraint. |
| 6 | Duplicate entry | `needs_check` + `[duplicate_entry]` on both rows | Confirmed. `verified` would assert the bibliography is fine when it demonstrably is not. |
| 7 | Orphan | `verified` + `[orphan]` | Confirmed. `orphan` derives from the claim map, not from resolution, so it can co-occur with any status; the corpus isolates it on an otherwise-clean reference. |
| 8 | Hallucinated reference | `unresolvable` + `[]` | Confirmed, plus a new corpus requirement: **every spiked paper must keep at least one genuine `unresolvable`**, or precision on `unresolvable` is unmeasurable. |
| 9 | What is a false accusation? | `conflict` on `injected: false`, **plus** any banned-term hit — both hard FAIL | Confirmed, with the banned-term clause added. `needs_check` on a clean reference is a false *alarm*: separate, non-blocking. |

Rulings 1 and 5 now include the **P5 mapping walk** that lands each on `needs_check`, step
by step through P5 step 3's rule order, so nobody has to re-derive it.

## Schema extension — four fields beyond the plan's example

The plan's example is a minimum shape and specifying this format *is* B3's job. Each field
exists to stop R2 inferring something from the `defect` free text, which FORMAT.md correctly
says is never scored.

| Field | Where | Required | Why it exists |
|-------|-------|----------|---------------|
| `defect_id` | per label | when `injected: true` | **Resolves 21 vs 23 without string matching.** Injections = distinct `defect_id`s (21); label rows = `injected: true` entries (23). Duplicate-entry rows share an id. **An id counts as matched only when ALL its rows match** — half-detecting a duplicate is not half a detection. Ids are assigned in the catalog *now*, globally unique across the corpus, so they never shift when papers are picked. |
| `control` | top level | yes | R2's release-blocking check must **read** which file is the control, never infer it from "every label is `injected: false`" — that inference breaks the moment a spiked paper is committed before its labels are written. |
| `source` | top level | yes | `{license, origin_url, origin_file}`. Makes R1's *"no copyrighted-restricted or student material"* DoD box **verifiable from the tree** rather than asserted in a PR. `license` is one of five allowed strings; a value outside the set is a hard error. `origin_file` names the untouched original for diffing. |
| `verified_by` / `verified_on` | per label | no | The audit trail for R1's *"a teammate spot-verifies 5 random labels"* test plan. Optional because most labels will never be spot-checked; present so the ones that were are recoverable months later. |

## Two gaps accepted as gaps

Both were considered and neither is being fixed. Recorded in FORMAT.md so nobody shoehorns
them in later.

1. **Document-level defects stay out.** P1's no-heading fallback (the last-15%-of-pages path)
   has no `ref_id` to attach to, and injecting it would re-index every other label in the
   file. It belongs in a **separate fixture PDF under `tests/`, owned by P1.** One line in
   FORMAT.md says so.
2. **`confidence`, `priority` and `checks[]` stay unlabelled** — labelling a confidence
   number would pin ground truth to an uncalibrated scale. **But the worklist is now
   assertable from the labels that already exist**, with no new field:
   - every reference in the top-3 worklist must have `injected: true`;
   - no version-pair trap may appear in the top-3 worklist (it is `verified`, severity
     `0.0`, so it belongs at the bottom).
   
   That catches the failure where per-status precision and recall both pass while the
   ordering a reviewer actually looks at is wrong — and the top-3 worklist is a demo beat.

## How I tested

No code, so verification is: does the specimen satisfy the spec? Run mechanically, not by
eye, against all 13 checklist items:

```
  1. PASS  exempt from stem==document (documented specimen); top-level keys exactly
           ['control', 'document', 'labels', 'source']
  2. PASS  control present and False (specimen is not the clean control)
  3. PASS  source keys exact; license "CC-BY" in the allowed five;
           origin_file "example_paper_original.pdf" is a bare filename
  4. PASS  10 labels for a 10-reference paper, one each
  5. PASS  ref_ids consecutive from R01, no gaps or duplicates: R01 … R10
  6. PASS  every expected_status is one of the four, exact lower case
  7. PASS  every indicator is one of the six, exact, no duplicates within an array
  8. PASS  every injected:true row has BOTH defect and defect_id; no injected:false row
           has either
  9. PASS  8 injected rows, 7 distinct defect_ids; shared: {'D06': 2} (duplicate pair,
           exactly 2 rows) -- specimen scale; corpus totals are 23 rows / 21 ids
 10. PASS  verified_by/verified_on always paired, dates ISO:
           [('R02','arsha','2026-09-03'), ('R07','roy','2026-09-03')]
 11. PASS  N/A - specimen is not the clean control
 12. PASS  N/A - specimen; the reason table lives in the catalog
 13. PASS  at least one genuine unresolvable with injected:false: ['R06']

  statuses (4/4) : ['conflict', 'needs_check', 'unresolvable', 'verified']
  indicators (6/6): ['doi_mismatch', 'duplicate_entry', 'malformed', 'orphan',
                     'retracted', 'version_mismatch']
```

Ruling 1's distinction is visible side by side in the specimen, which was the point of
adding the version-pair row:

```
  R04  needs_check   []                    <- wrong year
  R07  verified      ['version_mismatch']  <- real preprint/journal pair
```

The checklist earned its keep on the first pass by catching two real spec bugs — the
specimen's stem not matching its `document` field (which would have made R2 fail on a
human-only file), and the 21-vs-23 count that no validation step could then satisfy. Both
are fixed; the second is now `defect_id`.

## Statuses and indicators touched

All four statuses and all six indicators appear, as **specification text and expected values
only**. No code classifies anything here. The exact strings matter because R2 compares them
to contract enum values by string equality — hence FORMAT.md also specifies that `ref_id` is

as **sets**.
