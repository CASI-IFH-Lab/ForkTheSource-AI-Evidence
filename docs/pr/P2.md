## The pre-splitter, which is the part that had to be right

Plain Python, no model, tested alone against both papers before a single call was made.
Four behaviours, each from something P1 measured:

1. **Markers at line start, monotonic from 1.** Bracketed `[n]` first, then `n.` / `n)`,
   then a blank-line split for author-year styles. A wrapped line reading
   `"2014. Some continuation"` is not entry 2014, because 2014 is not the number due next.
2. **The appendix tail is truncated.** 26% of `sample.pdf`'s `references_text` is the
   attention-visualisation appendix. The last entry ends at `"...ACL, August 2013."`;
   no entry contains `Attention Visualizations`, `Input-Input Layer` or `siht`.
3. **Page furniture is dropped** — and both papers put it *between* entries, so left in
   it would glue onto whichever entry preceded it: bare page numbers `10`, `11`, `12` in
   the arXiv paper, and the running footer `PLOS Biology | DOI:... 8 / 9` three times in
   the PLOS one. The thresholds have a floor as well as a ceiling: without the 30-char
   length floor, `"arXiv:1607.06450, 2016."` (23 chars, 5 occurrences) would be deleted
   as a repeated line. There is a test for exactly that.
4. **Wrapped lines rejoin** with a space, except after a trailing hyphen where they join
   with none: `attention-\nbased` → `attention-based`, `pre-\nclinical` → `pre-clinical`.
   The printed hyphen is kept — removing it would be normalising beyond whitespace.

## ref_id — I did not choose this format

`R01`..`R40`: `R` + 1-based position, two digits, widening to three at 100+ references,
never mixed within a document. **This is specified in `eval/golden/FORMAT.md`**, which
calls it "the one coupling point" between the corpus and the pipeline. I checked it
before writing the function; my instinct had been `R001`, which would have broken every
one of Roy's labels while looking like catastrophic recall. Claim ids follow the same
width rule (`C01`), matching B1's ledger fixture.

## malformed

`Reference` forbids extra fields (Tier 1, frozen, Arsha's), so there is nowhere on it to
put a flag. The mechanism is a **derived predicate**:

```python
extractor.is_malformed(ref)   # True iff ref.title is None
```

Every printed reference has a title, and the prompt is instructed to return all-null
rather than guess, so a null title means extraction failed on that entry. P5 stamps
`Indicator.MALFORMED` on exactly these. The entry stays in the list with its `raw_text`
intact — **`len(out) == len(entries)` is asserted in code**, not only in a test, and
raises a `RuntimeError` naming it a bug if it ever fails.

## Determinism — the gate passes, and the reason is not the model. See D-101.

Gate as written — two runs on `sample.pdf`, byte-identical JSON, sorted keys: **PASSES.**
I then checked *why*, because a cache makes that gate free:

- Three runs with the disk cache bypassed, 40 real gateway calls each: byte-identical
  all three times.
- Those runs took **0.8–1.6s for 40 calls** — ~25ms each. **The gateway serves an
  exact-repeat request from its own cache**, so those three runs were not independent
  samples and prove nothing about the sampler.
- Probing the sampler directly (same entry, one trailing space so the request bytes
  differ): **5 of 6 entries identical.** The sixth returned two distinct outputs across
  six calls, differing in exactly one field — `venue: "arXiv preprint"` (4/6) vs
  `venue: null` (2/6). `title`, `authors`, `year`, `doi`, `arxiv_id` stable throughout.

Per the card, **the prompt was not reworded and the temperature was not retuned.** The
variance is in a field nothing downstream matches on. Full measurement, the cost, and the
rejected fix are in **D-101**.

## Cache

One JSON file at `settings.cache_dir()/extractor_cache.json` (gitignored), keyed on
`sha256(entry, model, temperature, PROMPT_VERSION, cache.schema_version)`. Atomic
temp-and-replace write after every entry, so a crash 30 calls into a cold run keeps the
30. A corrupt cache file is a miss, not a crash; a cached reply that no longer validates
is re-fetched rather than served as malformed.

`PROMPT_VERSION` is in the key because a reworded prompt produces different output from
the same entry, and serving the old answer would be a silent regression. **Bump it when
you touch `prompts.py`.**
