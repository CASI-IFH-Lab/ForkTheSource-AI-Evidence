## The guard — D-109

After a reply validates and before it is returned, a `doi` or `arxiv_id` the model
supplied that does **not** appear in the entry's printed `raw_text` is set to `None`,
noted, and warned. Comparison is on provenance, not format: both sides casefolded with
**all** whitespace removed (pdfplumber renders a real PLOS DOI as `10. 1016/j.ajpath…`),
and `arXiv:` / `doi:` / `https://doi.org/` / `abs/` / `CoRR abs/` / a trailing `vN`
stripped.

**Why it is structural and not a prompt instruction.** Our pitch is *"AI hallucinates
citations that look real; this tool catches them."* An extractor that invents a plausible
identifier is that exact failure inside the tool that claims to detect it — and it is
silent by construction, because an invented identifier **resolves**, so the reference ends
up looking *more* verified than one that honestly printed nothing. `paper1` R24 prints
`"…arXiv preprint (2017)."` with no id; the extractor returned `1706.05555`, which is a
real paper about BCS-BEC hydrodynamics; the `arxiv_id` branch treats an identifier as
*tying* the record to the reference, so the total disagreement that followed was reported
as a `conflict` — an accusation against a correctly-printed citation, built entirely on an
identifier we made up, landing on Roy's D20 trap row.

**Not marked `malformed`.** D-102's indicator means the extraction attempt produced
nothing usable. An entry whose title, authors and year are correct and whose id was
invented is a good extraction with one bad field; once the field is gone it resolves by
title like any other reference that printed none.

**`year` is deliberately not guarded** — it cannot cause a wrong resolution, and a
containment test over it fires on correct extractions. Recorded as a decision, with a test.

**`notes` is an optional trailing kwarg**, the same append-only shape as
`resolve(ref, notes=)`. `ExtractionResult` is unchanged, so `refs, malformed =
extract_references(doc)` still works everywhere. Because a caller may discard `notes`,
each drop **also** emits a `RuntimeWarning` — this is the one event that must never be
silent. P6 passes a list; the CLI prints an `extraction corrections` block above the
ledger path, so it is visible on stage.

## `scripts/precache_demo.py`

Runs the paper twice. **The second run is the test, not a repeat** — a cache written with
an unstable key looks identical to a warm cache on the run that wrote it, and only shows
up on the next one. So it compares the two on stored-reply count (must not grow), elapsed
time (must be under a warm threshold) and summary counts (must be identical), and exits 1
naming which failed. `--check-offline` is the single-run form for the Wi-Fi-off check.

```
cold  2.75s  30 refs  125 stored replies  {'verified': 23, ..., 'conflict': 2, 'unresolvable': 5}
warm  2.94s  30 refs  125 stored replies  {'verified': 23, ..., 'conflict': 2, 'unresolvable': 5}
```

**Offline proof.** I did not touch anyone's Wi-Fi. Instead the run was repeated with
`socket.socket` and `socket.create_connection` patched to raise — strictly stronger than
Wi-Fi off, which still permits a socket to be created and time out. Any attempt to reach a
registry or the gateway is an immediate loud error. Result: **`OFFLINE RUN OK 2.64s 30
refs`, counts identical.** The human Wi-Fi-off check is still worth doing once before
stage; `--check-offline` is the command.
